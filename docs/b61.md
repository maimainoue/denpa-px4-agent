# 4K (MMT/TLV) の復号 (ARIB STD-B61)

この文書は、4K 放送 (MMT/TLV) の限定受信を、このエージェントで復号する設計です。実装は `internal/b61` (TLV・MMTP・鍵の扱い) と `internal/card` (A-CAS カードへの問い合わせ) にあります。

## 1. 参考にしたもの

- [mmttmte/arib-b61-stream-test](https://github.com/mmttmte/arib-b61-stream-test) (Unlicense。`libaribb61/libaribb61.cpp`)。TLV から MMTP を取り出し、ECM をカードに渡し、AES-128-CTR で復号する流れを読みました。
- Unlicense は、コピー・改変・再配布が自由です。それでもコードは写さず、**考え方を読んで Go で書き直します**。この文書の値 (コマンド・テーブル番号・オフセット) は、その実装と、実機の A-CAS カードと 4K の放送波で確かめたものです。
- Apache-2.0 の libaribb25 と GPL-3.0 の recisdb-rs は、このプロジェクトの GPL-2.0 に取り込めないので、見ていません。

## 2. 範囲

| 含む | 含まない |
| ---- | -------- |
| TLV から IPv6 のヘッダー圧縮つきの MMTP を取り出す (CID ヘッダー型 `0x60` と `0x61`) | MMT のデコード (映像・音声の MFU の中身)。復号した TLV をそのまま流し、denpa 側で扱う |
| MMT-SI の PLT・MPT・CAT・ECM・EMM | MPEG-2 TS の復号 (これは `internal/b25`) |
| ECM → 鍵 (A-CAS のカード)、MFU のペイロードの AES-128-CTR の復号 | B-CAS カード (4K は A-CAS のカードだけ) |
| 鍵が変わる瞬間の扱い (偶数・奇数) | 契約の確認 |

- 復号できるのは、**A-CAS のカード**が開けていて、**契約のある番組**だけです。
- TS (先頭が `0x47`) と TLV (先頭が `0x7F`) は、最初の塊で決まります ([仕様書 7.5](spec.md))。TLV のときだけ、この復号を通します。

## 3. 全体の流れ

```
TLV の塊 ─→ TLV パケットに切る ─→ 圧縮 IPv6 なら MMTP を取り出す
                                      │
                    ┌─────────────────┴──────────────────┐
                    ▼                                    ▼
          信号 (payload type 2)                 データ (MPU)
   PLT → 番組の一覧 (MPT の packet id)           スクランブルされていれば
   MPT → 番組の ECM の packet id と                AES-128-CTR で復号
         スクランブルされた asset の一覧             (ECM の鍵)
   CAT → EMM の packet id                              
   ECM → カードに渡して鍵を貰う ───────────────────→ 鍵 (奇数・偶数)
   EMM → カードに渡す
```

- 出力は、入力と同じ TLV の並びです。復号したパケットは、スクランブルの印 (後述) を消し、同じ位置に同じ長さで書き戻します。
- TLV の外の余計なバイトは捨てます (同期バイト `0x7F` の前の残り)。ヌルパケット (`0xFF`)・IPv6 (`0x02`)・TLV-SI (`0xFE`) は、そのまま出します。

## 4. TLV パケット

| 位置 | 内容 |
| ---- | ---- |
| 0 | 同期バイト `0x7F` |
| 1 | パケット型。`0x02` IPv6、`0x03` ヘッダー圧縮 IP、`0xFE` TLV-SI、`0xFF` ヌル。それ以外は不正 |
| 2〜3 | 後ろの長さ (BE16) |
| 4〜 | 本体 |

- 同期バイトでなければ、次の `0x7F` まで読み飛ばします。型が不正なら、次の `0x7F` まで飛ばします。長さぶんが届いていなければ、次の塊を待ちます。
- 型 `0x03` (ヘッダー圧縮 IP) の本体は、先頭 3 バイトが `CID (12 ビット) | SN (4 ビット) | CID ヘッダー型`。ヘッダー型で MMTP の位置が決まります。

| ヘッダー型 | 意味 | MMTP の位置 (本体の先頭から) |
| ---------- | ---- | ---------------------------- |
| `0x60` | IPv6 (長さ抜き 38 バイト) と UDP (ポート 4 バイト) を持つ | 3 + 38 + 4 = 45 バイト |
| `0x61` | ヘッダー抜き (ペイロードだけ) | 3 バイト |
| それ以外 | 扱わない (不正として捨てる) | - |

## 5. MMTP パケット

| 位置 | 内容 |
| ---- | ---- |
| 0 | フラグ。`0x02` が拡張ヘッダーあり |
| 1 | 下位 6 ビットがペイロード型。`2` が信号 (MMT-SI)、`0` が MPU (データ) |
| 2〜3 | packet id (BE16) |
| 4〜7 | タイムスタンプ |
| 8〜11 | パケット順序番号 (BE32) |
| 12〜 | 拡張ヘッダーがあれば、種別 (BE16)・長さ (BE16)・本体。そのあとがペイロード |

### 5.1 拡張ヘッダーとスクランブル

- 拡張の種別が `0` のとき、本体は「拡張ヘッダーの並び」です。1 つは `終端フラグ (1 ビット) | 種別 (15 ビット)`・長さ (BE16)・値。
- 種別 `1` が**スクランブル制御**です。値の先頭バイトを `f` とします。

| ビット | 意味 |
| ------ | ---- |
| `(f >> 3) & 3` | `2` 偶数鍵、`3` 奇数鍵。ほかはスクランブルなし |
| `f & 4` | asset の識別子を持つ (1 バイト) |
| `f & 2` | MAC を持つ (2 バイト) |
| `f & 1` | IV を持つ (16 バイト) |

- IV は、制御のバイトの次から、識別子 (1)・MAC (2)・IV (16) の順に並ぶものとします。IV の長さが足りなければ、IV は無いものとします。
- **IV を持つパケットは、実機の放送波で見たことがありません。** 参考実装の IV の位置は、制御のバイトを数えていないように読めるので、ここでは制御のバイトの次としています (未確認)。見つけたら、ログに 1 回だけ出します。
- 復号したら、`f` の `(f >> 3) & 3` を 0 にします。

## 6. 信号 (MMT-SI)

payload type が `2` で、packet id が登録済みのものだけ読みます。

| packet id | 役目 |
| --------- | ---- |
| `0x0000` | PLT (番組の一覧) |
| `0x0001` | CAT (EMM の packet id) |
| PLT が指す packet id | MPT (番組の中身) |
| MPT が指す ECM の packet id | ECM |
| CAT が指す packet id | EMM |

### 6.1 断片の組み立て

ペイロードの先頭 2 バイトが断片の情報で、上位 2 ビットが断片指示です。

| 値 | 意味 |
| -- | ---- |
| `0` | 断片なし (そのまま 1 つのメッセージ) |
| `1` | 先頭 (バッファを空にして始める) |
| `2` | 途中 (足す) |
| `3` | 最後 (足して、メッセージとして読む) |

### 6.2 メッセージ

先頭は `message id (BE16)`・`version (1)`・`length (BE16)`。message id が `0x0000` (PA) と `0x8003` のときだけ、長さが 32 ビットで、続く 2 バイトを下位として足します (`length << 16 | 次の BE16`)。

| message id | 種類 | 読むもの |
| ---------- | ---- | -------- |
| `0x0000` | PA (PLT・MPT) | 中の表 |
| `0x8001` | CA (CAT) | 表 `0x86` |
| 上記以外 (ECM・EMM の packet id) | M2 | 表 `0x82` (ECM)・`0x84` (EMM) |

### 6.3 PA メッセージ

先頭の 1 バイト (表の数) が 0 のものだけ読みます。続く表のヘッダーは `table id (1)`・`version (1)`・`length (BE16)`。同じ version は読み飛ばします。

- **PLT (表 `0x80`)**: `パッケージ数 (1)`。パッケージごとに `ID の長さ (1, 必ず 2)`・`ID (= サービス ID)`・`場所の型 (1, 0)`・`packet id (BE16, MPT の場所)`。一覧にない MPT は捨てます。
- **MPT (表 `0x20`)**: `モード (1, 下位 2 ビットが 0)`・`ID の長さ (1, 2)`・`ID`・`記述子の長さ (BE16)`・`記述子`・`asset 数 (1)`。asset ごとに `識別子型 (1)`・`ID の体系 (4)`・`ID の長さ (1)`・`ID`・`asset 型 (4)`・`予約 (1)`・`場所の数 (1, 必ず 1)`・`場所の型 (1, 0)`・`packet id (BE16)`・`記述子の長さ (BE16)`・`記述子`。

記述子は `タグ (BE16)`・`長さ`。長さのバイト数はタグで決まります。

| タグ | 長さのバイト数 |
| ---- | -------------- |
| `0x4000`〜`0x6FFF` | 2 |
| `0x7000`〜`0x7FFF` | 4 |
| `0xF000` 以上 | 2 |
| それ以外 | 1 |

CA 記述子 (タグ `0x8004`): `ca_system_id (BE16)`・`場所の型 (1, 0)`・`packet id (BE16)`。`ca_system_id` が `0x0005` (A-CAS) のものだけ読みます。

- MPT 全体の CA 記述子の packet id が、その番組の **ECM の packet id** です。
- asset の記述子に CA 記述子があって packet id が `0xFFFF` なら、その asset はスクランブルされていません。それ以外の asset は、スクランブルされています。

### 6.4 CAT と EMM

- CAT (message `0x8001`、表 `0x86`): CA 記述子の packet id が EMM の packet id。前に登録した EMM の packet id と違えば、入れ替えます。
- M2 メッセージ: `table id (1)`・`長さ (12 ビット, 2 バイト)`・本体・CRC32 (4 バイト、読まない)。

### 6.5 ECM の表 (`0x82`)

本体の先頭 5 バイト (`表 ID の拡張 (2)`・`version (5 ビット)|current_next (1 ビット)`・`section 番号`・`最後の section 番号`) を除いた残りが、カードに渡す ECM です。

- `current_next` が 0 なら読みません。同じ version は、2 回目からは読み飛ばします。

### 6.6 EMM の表 (`0x84`)

先頭 5 バイトのあとに、エントリーが並びます。エントリーは `CAS モジュール ID (6)`・`長さ (1)`・本体 (長さぶん)。

- 長さが 2 未満で止めます。
- CAS モジュール ID が、カードの INT の応答にある ID と同じものだけ、`7 + 長さ` バイトをそのまま EMM としてカードに渡します。

## 7. 復号

- 鍵は ECM ごとに**奇数 16 バイト・偶数 16 バイト**です。
- 復号は **AES-128-CTR** で、対象は MMTP ペイロードの**先頭 8 バイト (MPU ペイロードのヘッダー) を除いた残り**です。
- IV:
  - IV を持っていれば、そのまま使います。
  - 無ければ、先頭から `packet id (2 バイト)`・`パケット順序番号 (4 バイト)`・`0 を 10 バイト` です。
- 鍵は、スクランブル制御が `2` なら偶数、`3` なら奇数です。
- 対象の asset は、MPT で「スクランブルされている」とされた packet id だけです。それ以外の MFU は、そのまま流します。

### 7.1 鍵が変わるとき

ECM の応答には、奇数と偶数の両方が入っています。片方は、いま使っている鍵と同じで、もう片方が次の鍵です。ECM が届いてカードの応答を待つ間 (数百ミリ秒) も、今の鍵で復号できるパケットは流す必要があります。

- ECM ごとに、**最後に変わった鍵 (奇数か偶数)** を覚えます。
- 新しい ECM を送って応答待ちの間に、パケットの鍵の型が、最後に変わった型と**同じ**なら、控えてある鍵で復号します。**違う型**のパケットが来たら、応答を待ちます (最大 4 秒)。
- 応答が来たら、奇数・偶数を控えている鍵と比べます。
  - 奇数が同じなら、変わったのは偶数。
  - 偶数が同じなら、変わったのは奇数。
  - どちらも違い、最後に変わった型が不明なら、そのパケットの型の反対側が変わったことにする。
- 4 秒待っても応答が無い、または応答が失敗なら、その ECM は失敗にして、その番組はスクランブルされたまま流します。失敗は 30 秒たつまで繰り返しません。

### 7.2 最初の塊を溜める

- 復号できる前の、スクランブルされた asset のパケットは、出力に溜めて (最大 16 MiB)、鍵が届いたら、位置を覚えておいて書き戻します。
- 次のどれかになったら、溜めたものを吐き出します。
  1. すべての番組の MPT が届き、すべての ECM がカードに渡った (応答が来たかは問わない)。
  2. すべての MPT が届いて、スクランブルされた番組が 1 つも無い。
  3. 溜めたものが 16 MiB を超えた。
  4. 入力が終わった (`Flush`)。

## 8. カード (A-CAS)

A-CAS のカードは、B-CAS 互換モードとは別の、**4K 用のコマンド**を持ちます。CLA は `0x90`、応答の返り値は応答の 5〜6 バイト目 (BE16)、末尾の 2 バイトがステータス (`90 00` で成功)。

| 名前 | コマンド | 応答 |
| ---- | -------- | ---- |
| INT (4K) | `90 30 00 01 00` | 19 バイト以上。返り値 `0x2100`。`ca_system_id` は 7〜8 バイト目 (BE16) で `0x0005`。CAS モジュール ID は 9〜14 バイト目 (48 ビット) |
| CKC (鍵の保護の設定) | `90 A0 00 01 10 00 00 00 01 00 00 8A F7 <8 バイト> 00` (8 バイトは `0`) | ちょうど 48 バイト。返り値 `0x2100`。7〜14 バイト目が応答の乱数 (8 バイト) |
| ECM | `90 34 00 01 <Lc> <ECM> 00` | 40 バイト以上。返り値が `0x0800`・`0x0600`・`0x4680` のどれか。7〜38 バイト目の 32 バイトが、保護された鍵 |
| EMM | `90 36 00 01 <Lc> <エントリー> 00` | 返り値 `0x2100` で受け入れ |

実機の A-CAS カードで、INT (4K) が 21 バイト (`00 11 00 00 21 00 00 05 09 21 9E A4 63 27 …  90 00`) を返すのを確かめました。CAS モジュール ID は、この例では `09219EA46327` です。

### 8.1 鍵の取り出し

1. CKC を送る。応答の 7〜14 バイト目を `r` とする (送った 8 バイトは `i` で、いまは `0`)。
2. `KCL = SHA-256(マスター鍵 32 バイト ‖ i ‖ r)`
3. ECM を送る。応答の 7〜38 バイト目を `c` (32 バイト) とする。
4. `h = SHA-256(KCL ‖ ECM の 5〜27 バイト目 (23 バイト))`
5. `鍵 = h XOR c`。前半 16 バイトが**奇数鍵**、後半 16 バイトが**偶数鍵**。

- CKC と ECM は、**間に他のコマンドを挟まずに**続けて送ります (挟むと鍵が化ける)。`internal/card` の問い合わせの順番待ちに入れて、まとめて 1 回で送ります。
- ECM の長さは 27 バイト以上です。
- マスター鍵は、参考実装 (Unlicense) にある 32 バイトの定数で、`internal/card/b61.go` に書きます。ARIB STD-B61 の限定受信の仕組みの一部で、このカードで復号するためのものです。
- 返り値が上の 3 つ以外なら失敗です。`0xA103`・`0x8901`・`0x8701`・`0x8902`・`0x8702`・`0x8903`・`0x8703`・`0x8700`・`0x8608` は「未契約」、それ以外は「理由不明」としてログに出します。
- カードがリセットされたら (`SCARD_W_RESET_CARD`)、開き直して 5 回まで試します。

## 9. このエージェントへの組み込み

- `manager.Config` に `NewTLVProcessor` を足します。選局の最初の塊が TLV のときに、これで復号を作ります (TS は今までの `NewProcessor`)。`SetDecrypt` が偽 (鍵の要る利用者がいない) なら、カードに問い合わせず、素通しです。
- `internal/card` に、4K 用の問い合わせを足します。
  - `B61Module()`: A-CAS のカードを開き、INT (4K) で CAS モジュール ID を返す。A-CAS でなければ「A-CAS のカードが要ります」。
  - `B61ECM(ecm)`: CKC と ECM をまとめて送り、32 バイトの鍵を返す。
  - EMM は、今ある `EMM` (順番待ち 16 件・1 秒に 1 件・同じものは送らない) を使う。
- ログ: カードを使い始めたときに `4K の復号を始めます (CAS モジュール ID …)`、ECM が失敗したときに理由を出します。

## 10. テスト

- **単体**: TLV の切り出し (欠けた塊・不正な型・ヘッダー型の違い)、MMTP の拡張ヘッダー、断片の組み立て、PLT・MPT・CAT・ECM・EMM の読み、IV の作り方、鍵が変わるときの待ちを、作った入力で確かめます。
- **往復**: 偽のカードで、既知の鍵から暗号化した MMTP を作り、復号の結果が元に戻ることを確かめます (MPT・ECM・暗号化した MFU を含む)。
- **実機**: 4K の放送波 (ケーブル) を録り、A-CAS カードで復号できるかを確かめます。契約が無い番組は、`ECM` の失敗がログに出ること、スクランブルされたまま流れることを確かめます。

## 11. 制限

- MMT の中身 (MFU・映像・音声) は解析しません。復号できたかは、denpa 側で見ます。
- 同じ番組を複数の利用者が見ても、鍵は 1 回の ECM の応答を共有します。
- ECM は番組 (サービス) ごとに 1 つずつカードに問い合わせます。多数の番組を同時に復号すると、カードの応答 (数百ミリ秒) が追いつかないことがあります。
- 契約の確認 (`POST /denpa/card/confirm`) は、4K には対応しません。

## 12. 実機での確認

リモートの VM (ケーブル回線・外付けの SCR3310 と A-CAS カード) で確かめました。

| 確かめたこと | 結果 |
| ------------ | ---- |
| QU39・QU42〜QU45・QC19〜QC22 (4K の MMT/TLV) を 10 秒ずつ録る | 全部で、ECM の応答を受け取れた。`復号したパケット 7,000〜30,000・復号できなかったパケット 0` |
| 復号した出力の MMTP | スクランブル制御がすべて `0` に消え、データの先頭 14 バイトが `00` で揃う (参考実装が「正しく復号できた」の判定に使う形) |
| 同じチャンネルを、カードなしで録る | スクランブル制御が `2` のまま、データは乱数。ログに `4K の復号を使えません: 使うカードリーダーがありません` を 1 回出して、素通しで流れる |

- 映像・音声として再生できるかは、denpa 側で確かめます (MMT の中身は、このエージェントでは解析しません)。
- 契約の無い番組を見たときの ECM の失敗 (`契約がありません (ECM の返り値 0xA103)` など) は、偽のカードの試験だけで、実機では確かめていません。
